# ADR-0002. Клиентский текст вместо анкеты аналитика

- **Статус:** предложено
- **Шаг:** 2 из 9 — приоритет 1
- **Связано с:** [0001](0001-priyomochnyy-kontur.md), [0003](0003-sborka-po-chastyam-i-rezyume-poslednim.md), [0004](0004-dokazatelstva-bez-steny-ssylok.md)

## Контекст

Жалоба: текст в отчёте нечитаем, выглядит машинным, не годится для бизнес-читателя.
Причина не в качестве модели, а в том, **какую форму мы просим её заполнить**.

Что измерено в коде и в эталонном прогоне `baselines/report-72`:

**1. Схема слайда — это анкета.** `SlideBodySchema`
(`orion-golden/deck-sections/contracts.ts:69–121`) состоит из полей
`whatWasFound` («Что обнаружено»), `whyItMatters` («Почему важно»),
`whatToCheck` («Что проверить»), `sourceNote` («Источник»). Каждая страница с
данными печатает эти четыре статические подписи с текстом под ними. Читатель
получает не статью, а бланк проверки, повторённый тридцать раз.

**2. Промпт требует плотности, а не смысла.** `ANALYST_BASE`
(`deck-sections/prompts.ts:24–34`) предписывает: «Для страниц с данными заполняй
**все** поля SlideBody», «Тексты не короче **~40% бюджета** соответствующего
поля». Нижняя граница длины — прямое указание разводить воду там, где сказать
нечего. Персона задана как «старший аналитик reputational due diligence», то есть
модель осознанно просят писать протоколом.

**3. У резюме два независимых автора.** Текст резюме собирается детерминированно
(`executive-summary/deterministic-composer.ts`) и одновременно существует
LLM-фрагмент `EXECUTIVE_SUMMARY` (`prompts.ts:58`). Это нарушение записанного в
`ENGINEERING.md` правила «Один вопрос — один ответ», и оно уже дало дефекты.

**4. Конкретные дефекты в готовом тексте** (`assembled-deck.json`, слайд «Резюме»):

> «Криминальные / судебные материалы: Предварительный сигнал: Криминальные /
> судебные материалы: 7 свидетельств (5 негативных) в источниках audit-it.ru,
> x.com, m.sledst.org, sledst.org. Примеры: Глинка Сергей (ИНН 773800015809) в
> реестре... · Связанный с Россией бизнесмен Сергей Глинка ...»

- **Тема продублирована трижды.** `toKeyFinding`
  (`deterministic-composer.ts:157–168`) кладёт тему в `title`, а в `factualBasis`
  пишет `${basisKindLabel}: ${finding.claim}` — и `claim` уже начинается с той же
  темы.
- **Счётчики вместо смысла.** «7 свидетельств (5 негативных) в источниках …» —
  это выгрузка из базы, а не предложение.
- **Согласование числительных сломано:** «4 свидетельств», «6 свидетельств
  (1 негативных)». Одного этого достаточно, чтобы текст читался как машинный.
- **Обрезка на полуслове** с многоточием и склейка через «·».
- **«Почему важно» — одна из четырёх заготовок.** `clientImpactFor`
  (`deterministic-composer.ts:171–182`) возвращает фиксированное предложение по
  уровню риска. На весь отчёт — четыре варианта, поэтому раздел выглядит
  шаблонным, каким он и является.
- **Поисковые подсказки поданы как доказательство:** «Примеры: Сергей Глинка ·
  глинка сергей михайлович жена · глинка сергей михайлович дети». Строчные
  сырые запросы в резюме для состоятельного клиента.

## Решение

Заменить анкету на редакторскую структуру и снять требования, которые портят текст.

1. **Новый контракт тела слайда.** Вместо `whatWasFound` / `whyItMatters` /
   `whatToCheck` — поля, из которых собирается связный текст:
   - `lead` — один абзац, который можно прочитать вслух и понять без остального
     слайда;
   - `body` — 1–2 абзаца развития;
   - `takeaway` — вывод для решения;
   - `evidence` — структурированные ссылки на доказательства (см. [0004](0004-dokazatelstva-bez-steny-ssylok.md)),
     **не текст**.
   Статические подписи «Что обнаружено / Почему важно / Что проверить» с макета
   убираются: их роль выполняет сам текст.
2. **Убрать нижнюю границу длины.** Требование «не короче 40% бюджета» удаляется.
   Вместо него — верхняя граница и правило «нет материала — короче, а не
   водянистее». Пустое состояние уже разрешено правилами продукта.
3. **Сменить персону промпта.** Не «старший аналитик», а деловой журналист,
   пишущий для руководителя: короткие предложения, активный залог, конкретика
   вместо канцелярита. Запреты (не добавлять фактов, не приписывать субъекту
   чужие материалы) сохраняются дословно — это требования продукта.
4. **Один автор у каждого текста.** Детерминированный композитор остаётся
   источником **структуры и чисел**; формулировки — за LLM. Дублирующая
   заготовка `clientImpactFor` удаляется.
5. **Числа — через правильное согласование.** Склонение числительных выносится в
   одну функцию и покрывается тестом; в шаблоны числа больше не вклеиваются
   конкатенацией.
6. **Тема не повторяется.** `factualBasis` перестаёт начинаться с темы, раз тема
   уже стоит заголовком.

## Последствия

- Ломается формат `SectionPack` — потребуется миграция пакетов секций и правка
  шаблонов рендерера. Мы не в проде, breaking change допустим.
- Эталон `baselines/report-72` перестанет совпадать: его нужно перегенерировать
  и принять заново как новый эталон.
- Текст станет короче. Часть страниц, живших за счёт заполнения полей, окажется
  полупустой — это вход в [0008](0008-vizualnyy-yazyk-prezentatsii.md).

## Глобальное тестирование после шага

- `npm run ci` зелёный (гейт из [0001](0001-priyomochnyy-kontur.md)).
- Автопроверка на золотом кейсе: в клиентском тексте отсутствуют «свидетельств»,
  «Предварительный сигнал:», повтор темы в начале `factualBasis`, многоточия
  обрезки, сырые подсказки в резюме.
- Тест на согласование числительных: 1/2/5/11/21/104 свидетельства.
- Ни один из четырёх шаблонов `clientImpactFor` не встречается в выдаче.
- Ручная вычитка одной страницы каждого типа — читается как текст, а не бланк.
