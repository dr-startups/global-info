# ADR-0006. Типографика и метрики рендерера

- **Статус:** предложено
- **Шаг:** 6 из 9
- **Связано с:** [0007](0007-proverka-verstki-po-tomu-chto-vidit-chelovek.md), [0008](0008-vizualnyy-yazyk-prezentatsii.md)

## Контекст

Жалобы по презентации: «странные шрифты» и «текст выезжает за блоки». У обеих —
одна общая причина в одном файле.

**1. Шрифт — свободный системный, а не типографика продукта.**
`renderer/orion_golden_render/common.py:40`: `FONT = "DejaVu Sans"`. DejaVu — это
шрифт по умолчанию в Linux, метрически совместимый запасной вариант. Он не
нейтрален: у него широкие пропорции и характерный рисунок, который читается как
«документ, свёрстанный чем попало». Для отчёта, который продают состоятельному
клиенту, это заметно сразу.

Смена шрифта сейчас заблокирована кодом: `assert_render_font_family`
(`common.py:208–215`) **падает на старте**, если резолвится не DejaVu. Проверка
писалась, чтобы измерение и вывод не разъезжались, — но заодно она делает
типографику неизменяемой.

**2. Жирный текст меряется метриками обычного начертания.**
`_font_path()` (`common.py:190–206`) возвращает единственный файл —
`DejaVuSans.ttf`. При этом жирность в слайдах ставится через python-pptx
(`r.font.bold = True`, например `common.py:752`, `990`, `1191`). Значит:

- ширина строки считается по **обычному** начертанию;
- рисуется **жирное**, которое шире;
- реальная строка не влезает в отведённое место.

Это и есть «текст выезжает за блоки»: заголовки, подписи и первые строки
маркированных пунктов — ровно те места, где стоит жирность. Файл
`DejaVuSans-Bold.ttf` в репозитории лежит, но для измерения не используется.

**3. Запасная оценка ширины — счёт символов.**
Когда PIL не смог загрузить шрифт, ширина берётся как
`len(trial) * font_size_pt * 0.58 * 96 / 72` (`common.py:179`, `182`) — то есть
все символы считаются одинаковой ширины. Для пропорционального шрифта это
неверно всегда; для строки из «ш», «ж», «м» ошибка кратная.

**4. Мелочь того же происхождения.** В списке путей к шрифту
`/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf` указан дважды.

## Решение

1. **Разделить «какой шрифт» и «согласованы ли метрики».** Проверка на старте
   перестаёт требовать именно DejaVu. Требование становится осмысленным:
   *шрифт, которым меряем, совпадает со шрифтом, которым рисуем, и оба
   начертания доступны*. Несовпадение по-прежнему валит старт.
2. **Подключить нормальную гарнитуру.** Выбирается шрифт с лицензией,
   допускающей встраивание, с кириллицей и как минимум четырьмя начертаниями
   (Regular / Medium / SemiBold / Bold). Файлы кладутся в `renderer/fonts/` и
   ставятся в образ, чтобы LibreOffice отдавал тот же рисунок при конвертации в
   PDF. Конкретная гарнитура фиксируется в [0008](0008-vizualnyy-yazyk-prezentatsii.md) вместе с остальным
   визуальным языком.
3. **Мерить тем начертанием, которым рисуем.** `_font_path()` заменяется на
   резолвер, принимающий начертание (`regular` / `bold` / …). Все места
   измерения получают то же начертание, что задаётся тексту.
4. **Убрать оценку по числу символов.** Отсутствие шрифта для измерения — это
   отказ, а не повод считать приблизительно: рендер останавливается с внятной
   ошибкой. Тихая неточность здесь дороже явного падения — по тому же правилу,
   по которому в этом проекте `CONTENT_DROPPED_BY_RENDERER` стал CRITICAL.
5. Убрать дубль пути.

## Последствия

- Меняется вся вёрстка: другой шрифт — другие переносы, другое число строк на
  странице. Эталон презентации переснимается целиком.
- Образ рендерера вырастет на размер шрифтовых файлов (единицы мегабайт).
- Часть страниц, которые «влезали» из-за заниженной оценки ширины, перестанет
  влезать — и это станет видно. Обработка таких страниц — в [0007](0007-proverka-verstki-po-tomu-chto-vidit-chelovek.md).
- Нужна проверка лицензии на встраивание шрифта в PPTX/PDF, отдаваемый клиенту.

## Глобальное тестирование после шага

- `npm run ci` зелёный.
- Тест метрик: измерение строки жирным начертанием даёт ширину больше, чем
  обычным, на одном и том же тексте. Сейчас этот тест красный — в этом суть шага.
- Тест старта: несовпадение шрифта измерения и вывода валит рендерер.
- Отсутствие файла шрифта даёт явную ошибку, а не приблизительный расчёт.
- Перегенерация золотой деки: PPTX и PDF показывают одну гарнитуру, кириллица не
  подменена запасным шрифтом.
