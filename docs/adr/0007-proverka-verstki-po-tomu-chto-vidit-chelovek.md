# ADR-0007. Проверка вёрстки — по тому, что видит человек

- **Статус:** предложено
- **Шаг:** 7 из 9
- **Связано с:** [0006](0006-tipografika-i-metriki-renderera.md), [0008](0008-vizualnyy-yazyk-prezentatsii.md)

## Контекст

Здесь зафиксирован самый неприятный факт этой переработки.

Пользователь видит, что **текст выезжает за блоки**. Инспектор геометрии на том
же самом прогоне сообщает
(`baselines/report-72/artifacts/deck-sections/geometry-report.json`, 41 слайд):

```
overlaps: 0    overflow: 0    clipping: 0    emptyPages: 0
```

Проверка зелёная на деке, которую человек называет сломанной. Причина — в
определении. `inspectSlideXmlGeometry`
(`orion-golden/classic/generate-first36-geometry-artifacts.ts:210–224`) считает
переполнением **только выход рамки фигуры за границы слайда**:

```ts
if (outOfBounds(s.bbox)) {
  overflow.push({ code: "out-of-bounds", severity: "CRITICAL", … });
}
```

Но текст, не помещающийся в свой блок, **не двигает рамку блока**. Рамка
остаётся на месте, внутри границ слайда, и проверка её пропускает. Ровно тот
дефект, на который жалуется пользователь, невидим для проверки по построению.

Хуже: длина строки, по которой рендерер решает, сколько текста поместится,
считается теми же метриками, что описаны в [0006](0006-tipografika-i-metriki-renderera.md) — заниженными для
жирного начертания. То есть **проверка меряет тем же испорченным инструментом,
который создаёт дефект**, и поэтому не может его увидеть. Проверка
подтверждает сама себя.

В этом же репозитории уже записано правило на этот счёт: «Тихая потеря
содержимого хуже пустоты» — и выброс блоков рендерером был доведён до
`CONTENT_DROPPED_BY_RENDERER` уровня CRITICAL. Переполнение осталось
незакрытым.

## Решение

Проверять результат, а не намерение: смотреть на отрисованную страницу.

1. **Переполнение переопределяется.** Добавляется класс дефекта «текст не
   помещается в свою фигуру»: сравнивается требуемая высота текста при заданном
   кегле и ширине с внутренней высотой фигуры за вычетом полей. Это ловит
   именно тот случай, который сегодня проходит.
2. **Проверка по растру, независимая от наших метрик.** Страницы уже
   рендерятся в PNG (`pages-png/`, шаг `orion:deck-sections-report72`). На
   растре проверяется то, что нельзя подделать расчётом:
   - тёмные пиксели вне безопасной области страницы;
   - пересечение текстовых пятен с границами карточек;
   - обрезанная строка у нижнего края блока.
   Это второе мнение: оно не пользуется тем же кодом измерения, что и рендерер,
   поэтому не наследует его ошибку.
3. **Ноль перестаёт быть достаточным ответом.** Проверка сообщает не только
   число дефектов, но и **сколько страниц реально проверено**. Отчёт вида
   «0 дефектов на 0 проверенных страниц» становится невозможным — это прямое
   следствие [0001](0001-priyomochnyy-kontur.md).
4. **Эталон вёрстки.** Растровые страницы золотой деки фиксируются как эталон,
   и расхождение сверх порога останавливает сборку. Сами PNG в репозиторий не
   коммитятся (это уже закреплено в `.gitignore`) — сравнение идёт с
   артефактом прогона.
5. **Переполнение — ошибка, а не примечание.** Страница с невлезающим текстом
   не отдаётся клиенту: либо текст сокращается на этапе сборки, либо блок
   переносится на следующую страницу — механизм переноса уже есть
   (`semantic-summary-pagination.ts`).

## Последствия

- Сразу после включения проверка станет красной на реальных дефектах. Это
  ожидаемо: сейчас она красной быть не может.
- Прогон удлиняется на растровую проверку (десятки секунд на деку).
- Проверка требует отрендеренных страниц, то есть работающего рендерера, —
  значит, живёт в `ci:full`, а не в офлайновом `ci`.

## Глобальное тестирование после шага

- `npm run ci` зелёный, `npm run ci:full` включает растровую проверку.
- Контрольный дефект: слайд с заведомо избыточным текстом ловится и по расчёту,
  и по растру. Фикстуры для этого уже есть
  (`orion-golden/classic/fixtures/geometry/clipping-overflow.json`).
- Отчёт проверки содержит число проверенных страниц, и оно равно числу страниц
  деки.
- Золотая дека проходит проверку без единого переполнения — после исправлений,
  которые эта проверка вскроет.
