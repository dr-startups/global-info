# ADR-0008. Визуальный язык презентации

- **Статус:** предложено
- **Шаг:** 8 из 9
- **Связано с:** [0002](0002-klientskiy-tekst-vmesto-formy-analitika.md), [0006](0006-tipografika-i-metriki-renderera.md), [0007](0007-proverka-verstki-po-tomu-chto-vidit-chelovek.md)

## Контекст

Требование: презентация должна выглядеть так, чтобы её можно было продавать
состоятельному клиенту, следящему за своей репутацией. Сейчас — «как будто делал
пятиклассник».

Важно точно назвать причину, иначе переделка уйдёт не туда. **Палитра здесь
почти ни при чём.** В `renderer/orion_golden_render/common.py:57–74` заданы
осмысленные токены: тёмно-синий `#0B1A33`, приглушённый текст `#64748B`, акцент
`#3B82F6`, золото `#C09A4F`, тональные фоны для риска/предупреждения/нормы. Это
не работа пятиклассника.

Ощущение дешевизны создают три другие вещи, и две из них уже разобраны:

1. **Гарнитура** — свободный системный DejaVu ([0006](0006-tipografika-i-metriki-renderera.md)).
2. **Текст, выезжающий за блоки** ([0007](0007-proverka-verstki-po-tomu-chto-vidit-chelovek.md)). Ничто так не удешевляет
   документ, как строка, наехавшая на рамку.
3. **Плотность и ритм.** Схема слайда — анкета из четырёх подписей
   («Что обнаружено / Почему важно / Что проверить / Источник»), которую
   промпт обязан заполнить целиком, да ещё не короче 40% бюджета поля
   ([0002](0002-klientskiy-tekst-vmesto-formy-analitika.md)). В результате каждая страница — плотный
   равномерный текстовый ковёр без воздуха и без иерархии: глазу не за что
   зацепиться, все блоки выглядят одинаково важными.

Отдельно: 41 слайд на один отчёт. Для читателя, ради которого делается документ,
это не презентация, а брошюра.

## Решение

Собрать визуальный язык как систему, а не править отдельные страницы.

1. **Типографическая шкала.** Фиксированный набор размеров и начертаний
   (заголовок раздела, заголовок страницы, лид, основной текст, подпись,
   сноска) с заданными межстрочными интервалами. Произвольные кегли в коде
   слайдов запрещаются: размер выбирается из шкалы.
2. **Модульная сетка и воздух.** Единая сетка колонок, единые поля, обязательное
   свободное поле у нижнего края. Плотность перестаёт быть переменной, которую
   подгоняют под объём текста: если текст не влез — сокращается текст или
   добавляется страница ([0007](0007-proverka-verstki-po-tomu-chto-vidit-chelovek.md)), а не уменьшается кегль.
3. **Иерархия вместо равномерности.** На странице ровно один элемент первого
   уровня — лид или ключевая цифра. Остальное — заведомо тише. Это то, чего
   сейчас нет совсем.
4. **Палитра остаётся, использование сужается.** Существующие токены
   сохраняются; запрещается раскрашивать текст ради разнообразия. Цвет несёт
   один смысл — уровень риска, и только там, где он про риск.
5. **Типы страниц вместо страниц.** Закрепляется небольшой набор шаблонов
   (титул, оглавление, лид раздела, страница находки, страница с визуалом,
   таблица, приложение). Реестр шаблонов уже существует
   (`deck-sections/template-registry.ts`) — он становится закрытым списком.
6. **Короче.** Целевой объём клиентской части — существенно меньше 41 страницы;
   вытесненное уходит в приложение. Точная цифра ставится после [0002](0002-klientskiy-tekst-vmesto-formy-analitika.md),
   когда станет видно реальный объём текста.
7. **Обложка и оглавление под задачу.** Первая страница — не «Отчёт о цифровом
   профиле» служебным набором, а титул документа, который не стыдно положить на
   стол.

## Последствия

- Шаблоны рендерера переписываются существенно; это самый объёмный шаг по коду
  после [0002](0002-klientskiy-tekst-vmesto-formy-analitika.md).
- Часть содержания переезжает в приложение — нужна сверка, что ничего не
  потеряно (правило «тихая потеря содержимого хуже пустоты»).
- Шаг делается **после** [0006](0006-tipografika-i-metriki-renderera.md) и [0007](0007-proverka-verstki-po-tomu-chto-vidit-chelovek.md): верстать по
  сломанным метрикам и без работающей проверки переполнения бессмысленно.

## Глобальное тестирование после шага

- `npm run ci` и `npm run ci:full` зелёные, растровая проверка без переполнений.
- Автопроверка шкалы: в отрисованной деке не встречается кегль вне списка.
- Автопроверка иерархии: на каждой странице ровно один элемент первого уровня.
- Число страниц клиентской части — в целевом диапазоне; полнота содержания
  подтверждена сверкой с приложением.
- Показ готовой деки заказчику как приёмка DoD: «на голову выше» — оценка
  человека, и она снимается человеком.
