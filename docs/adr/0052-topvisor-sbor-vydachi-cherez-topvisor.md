### T4. Блок «Частота» — ждёт данных, а не кода

`edit/keywords_2/volumes/go` **списывает деньги и значений не отдаёт**: на пилоте 1,06 ₽ списаны
03.09 в 07:07, за 93 минуты и 20 опросов `volume:0:225:{1,2,3}` у всех 59 фраз остались `null`.
Возврата в кассе нет, заказ принят: до запуска сервис принимал только квалификатор `0:225:2`
(от тулбоксовой задачи), после — типы 1, 2 и 3, то есть слот заведён. Статуса у частоты нет:
полей `status_volumes*` в проекте не существует. Даты в запросе картину не меняют; выключенная
группа подбора ни при чём — у включённых RU и UAE частоты нет ровно так же.

Порядок: **перечитать бесплатно** (`get/keywords_2/keywords` с
`fields: ["name", "volume:0:225:2"]`); если пусто — вопрос в поддержку Topvisor с номером
проекта, временем заказа, суммой и формой чтения. Блок «Частота» строить не на чем, пока значения
не пришли: страница с пустой колонкой хуже отсутствующей страницы.

### Умолчание `SERP_COLLECTION_PROVIDER` — решение владельца

Код к переключению готов: `legacy` → `topvisor` в `config/defaults.ts` — одно значение. Не
переключено намеренно: **путь Topvisor ни разу не проходил живой прогон целиком.** Пилот трогал
API руками, конвейер — только на фикстурах. Первым должен быть один платный прогон на реальном
кейсе, и разрешение на него даёт владелец.

### Открытые вопросы владельцу

1. **Два проекта Topvisor на кейс** (RU и UAE) против переплаты ≈ ×1,8: сейчас один проект, и все
   фразы проверяются во всех регионах.
2. **Подсказки для набора запросов** по-прежнему спрашиваются у Serper (решение владельца
   03.09) — это не поверхность отчёта, а планирование. Перевод на Topvisor означал бы строить
   набор запросов уже собранными подсказками, то есть после сбора.
3. **Честное пустое состояние** для поверхностей подсказок, если список сузят: ячейки покрытия
   для Topvisor не заводятся, и страница без данных может сказать «сбор выполнен, по региону
   пусто» вместо «не собирались».
