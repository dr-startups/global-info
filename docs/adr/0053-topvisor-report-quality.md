# 0053 — Качество отчёта после первого прогона Topvisor

План шага. Основание — сравнение отчётов 82 (без Topvisor) и 83 (с Topvisor) по кейсу
DPA-2026-0050, файл `compare/comparison.md` в scratchpad шага. Дефекты сгруппированы по
одному признаку: **что увидит клиент после правки**. Ветка — `feature/topvisor`.

## Что чинить

### A. Таблицы ТОП-20 подписаны не тем запросом (регресс)

Признак: над таблицей «основной запрос не отмечен» или запрос «…инн», заголовок без «позиции 1–20».
Причина: `pickSerpTableQuery` выбирает запрос с `queryPurpose === "subject_lookup"`, а у строк
Topvisor назначения нет — `loadTopvisorKeywordsFromDb` читает только текст запроса, и
`snapshotToObservations` его не несёт. Базовые строки получают назначение из плана запросов
(`orion-search-profile-service.ts`, `querySpec.purpose`).

Правка: план запросов уже детерминирован по субъекту (так его берёт `yandex-gen-answer-collection.ts`
через `queriesForRegionPurpose`). Тик Topvisor получает назначение каждого ключевого слова из того
же плана и кладёт `queryPurpose` в наблюдение; слияние (`composite-serp-merge.ts`, ветка
наблюдений обогащения) передаёт его дальше, как уже делает для базовых строк.

Тесты: `topvisor-snapshot-becomes-organic-rows` — строка запроса субъекта несёт
`queryPurpose: subject_lookup`; `topvisor-rows-merge-into-engine-tables` — после слияния
`pickSerpTableQuery` возвращает запрос субъекта на наборе из одних Topvisor-строк. Мутация:
убрать передачу назначения в слиянии — таблица снова подписывается «…инн».

### B. Негативная подсказка не видна на панели

Признак: сайдбар говорит «в собранном наборе есть 1 негативная формулировка», панель её не рисует.
Причина: `buildListPanelAsset` берёт первые 10 строк в порядке сбора.

Правка: строки панели упорядочиваются «негативные первыми, остальные в порядке сбора», после чего
`slice(0, 10)`. Красная строка с меткой «нежелательный» в SVG уже есть (`buildSurfacePanelSvg`).
Статусная строка про «негатив есть, но на панель не попал» остаётся — она сработает, когда
негативных больше десяти.

Тесты: `canonical-visual-assets` — на 12 строках с негативной двенадцатой панель рисует её первой и
`visibleItems[0].adverse === true`. Мутация: вернуть исходный порядок — тест красный.

Открытый вопрос владельцу (В1): «судимости» и «криминал» — две очевидно негативные подсказки, а
классификатор насчитал одну. Расширять словарь подсказок словом «криминал» или оставить как есть?

### C. AI-ответы: текст не печатается, копии, нет движка, «N результатов»

Признак на странице 83/50–55 и 80–83: одна и та же картинка на шести листах, под ответом четыре
строки «Ответ поискового ИИ», сайдбар «Показано 32 результата».

Четыре причины, четыре правки:

1. **Текст ответов не печатается.** Шаблон `ai-overview` объявляет `layout("single-column")` и
   буллеты, а рендерер по `rendererTemplate: orion_golden_surface_panel` идёт в
   `_render_visual_with_sidebar`, который буллеты не рисует (в `visual.py` они только участвуют в
   условии `has_sidebar`). Продолжения существуют потому, что буллеты есть, и выходят пустыми.
   Правка на стороне рендерера: для `ai-overview` рисовать панель сверху (уменьшенной) и буллеты
   под ней в одну колонку, продолжения — только буллеты. Гейт `smoke_deck_raster_layout.py`
   получает страницу с ответом и проверяет, что текст ответа на растре присутствует, а
   продолжение без буллетов не создаётся. Это **окно деплоя**: старый рендерер нарисует страницу
   без отказа (как сейчас) — предупредить владельца.
2. **Копии «Ответ поискового ИИ».** Панель берёт 4 «факта» из следующих строк, а это
   строки-источники, у которых заголовка нет, и `ANSWER_TITLE_FALLBACK` подставляет одно и то же.
   Правка: строка-источник получает заголовком домен страницы (`publicDomainOf`), а панель для
   `ai_answer` вместо «фактов» печатает список источников «домен — путь» (или ничего, если их нет).
   Тот же заголовок увидит `sourceLine` в буллетах: «Источник: tass.ru — tass.ru» станет
   «Источник: tass.ru/…».
3. **Нет подписи движка.** `buildKnowledgePanelSvg` не имеет `engineLabel`. Правка: добавить, панель
   печатает «Алиса (Яндекс)» / «Google AI Overview» по `engine` выбранного ответа.
4. **«Показано N результатов».** Для `ai-overview` `pageFindingBlocks` даёт общую строку состава.
   Правка: строка состава для поверхности AI считает **ответы** («Ответов: 2 — Алиса 1, Google 1;
   источников в ответах: 8»), а не ссылки.

Тесты: `topvisor-ai-answers-are-quoted-with-sources` расширяется на заголовки источников;
новый `ai-overview-prints-answers` на построителе (буллеты присутствуют и разбиты по предложениям,
строка состава считает ответы); Python-смок растра для страницы ответа. Мутации: убрать
`engineLabel` — красный; вернуть fallback-заголовок — красный.

Открытый вопрос владельцу (В2) — **сколько ответов печатать.** Сейчас по одному ответу на каждый
запрос (16 в России, 9 в ОАЭ). Варианты:
- (а) один ответ на движок и регион — по запросу субъекта (`subject_lookup`); остальные ответы
  остаются в данных и в приложении, на странице их нет. Страниц: 1–2 на регион;
- (б) как (а), плюс строка «ещё N ответов по дополнительным запросам, негативных M» и отдельная
  страница с негативными ответами, если они есть;
- (в) все ответы, как сейчас, но с текстом — 6–10 страниц на регион.
Рекомендация: (б) — читатель видит один ответ на движок, а негатив из остальных не теряется.

### D. dzen.ru: не прочитано, но «криминал»

Признак: строка с «не прочитано» и темой «Криминальные / судебные материалы».
Причины: (1) Дзен отдаёт HTML без текста обычному `fetch` → `empty_text`; (2) тема назначена по
сниппету выдачи словарём (`уголов|…`), а в сниппете уголовное дело у другого лица.

Правки:
- В отчёте непрочитанная страница с темой из сниппета так и подписывается: «тема по сниппету
  выдачи; страница не прочитана» — и не входит в счёт «негатив среди прочитанных». Это
  требование продукта: утверждение прослеживается до наблюдения, и наблюдение здесь — сниппет.
- Читалка получает второй способ для доменов, которые отдают пустой HTML: браузерный захват уже
  есть в `serp-capture/playwright-capture.ts`. Список доменов — данные (`config/defaults.ts`,
  `LINK_READER_BROWSER_DOMAINS: "dzen.ru"`), не флаг.

Открытый вопрос владельцу (В3): включать браузерное чтение в этот шаг (дороже по времени прогона,
Playwright в контейнере `app`) или ограничиться честной подписью? Рекомендация: подпись сейчас,
браузерное чтение отдельным шагом.

### E. Квадраты вместо иероглифов

`renderer/Dockerfile`: добавить `fonts-noto-cjk`. Проверка: `smoke_deck_raster_layout.py` получает
строку с китайским заголовком и проверяет, что в растре нет «tofu» (пиксельная проверка ячейки:
ненулевая доля тёмных пикселей внутри контура символа, а не сплошная рамка). Окно деплоя не
нужно: образ пересобирается вместе с рендерером.

### F. Пустая страница подсказок ОАЭ называет ложную причину

Страница 83/74: «инструмент сбора не входил в состав прогона», а Topvisor вызывался и вернул 0.
Правка: причина берётся из состояния прогона — `suggest[].ready === true` и нулевой результат →
«Topvisor вернул 0 подсказок по запросу «…» (Google, Дубай)». Тест на `coverage-empty-state`.

Открытый вопрос владельцу (В4): подсказки Google в России и ОАЭ. Topvisor их не даёт (Россия —
отказ провайдера, Дубай — пусто). Варианты: (а) оставить только Яндекс; (б) подсказки Google
собирать Serper/Arsenkin как раньше, при `SERP_COLLECTION_PROVIDER=topvisor` тоже — это возврат
одного инструмента базового сбора для одной поверхности. Рекомендация: (б), иначе в ОАЭ поверхность
подсказок пуста всегда.

## Вне рамок

- Частота запросов (T4) — Topvisor не отдаёт значения, вопрос в поддержке.
- Переключение умолчания `SERP_COLLECTION_PROVIDER` на topvisor — после закрытия В4.

  дефект шаблона тем, заводится следующим шагом.
