# 0056 — Ни один кейс не возвращает ошибок

Статус: план, до первой строки кода. Основание — прогон DPA-2026-0053 («Егоров
Алексей Евгеньевич»), четыре отказа подряд на одном кейсе: `ASSEMBLY_FAILED`
(домен в подписи, дважды), `ASSEMBLY_QA_FAILED` (повтор текста),
`CONTENT_DROPPED_BY_RENDERER` (стр. 62). Задание владельца 05.09.2026: «найди
вообще все ошибки, которые могут возникнуть, и сделай так, чтобы ни в одном
кейсе они не возникали». Артефакты обоих прогонов сняты с тома Railway по SSH
в `scratchpad/0060/run/` (материалы живого человека — в репозиторий не идут).

## 1. Почему четыре отказа на одном кейсе

1. **Шаг 0054 изменил форму данных**, а дека никогда её не видела. Режим по
   якорям дал 201 `LIKELY_SUBJECT`, 415 `AMBIGUOUS`, кириллическое имя издания
   в заголовке («Закон.ru»), описание с пропущенным пробелом («court.Read»),
   английский ответ ИИ на 1134 знака. Оба эталона (`report-72`, `golden-case`)
   — прогоны без якорей; на них 28 ворот приёмки зелёные, и это ничего не
   говорило о новой форме.
2. **Ворота стоят в конце оплаченного конвейера и закрыты наглухо**: 21 из 22
   фрагментов обязательны, любое из 24 замечаний секционной проверки роняет
   деку целиком. Цена ложного срабатывания — отчёт не выдан; цена пропуска —
   один дефектный блок. Пороги существенности есть только у трёх текстовых
   эвристик сборки.
3. **Отказ называл следствие, а не причину** («домен xn--80ankme.ru»,
   «страница 62»), и каждая правка стоила выката и получасовой попытки; две
   правки из четырёх были не туда.
4. **Не было офлайн-реплея настоящего прогона** через сборку и отрисовку: каждый
   дефект открывался только в проде.
5. **Ёмкость сайдбара согласована с рендерером только для буллетов** (цикл
   «мера → перекладка → пересборка», `runDeckBuildMeasured`). Страница
   AI-ответов, заведённая для Topvisor, ужала сайдбар до трети листа
   (1,6 млн EMU ≈ 6 строк по 35 знаков), а дека кладёт в него 660 знаков;
   смок страницы проверял текст в 150 знаков и не мог этого увидеть.

## 2. Опись всего, что останавливает прогон (по коду)

- **Аналитика, детерминированные гейты** (`assert*GatesPass`): покрытие тем,
  учёт P1/P2, обрывы цитат, трассировка утверждений, учёт наблюдений,
  метрики, пакет резюме (17 кодов) и `SUBJECT_ANCHORS_NO_MATCH` (намеренный
  стоп 0054). На 0053 все прошли.
- **Секционная проверка** (14 проверок, 24 места отказа): схема, происхождение,
  неизвестные идентификаторы, OTHER_SUBJECT в KPI, бюджеты полей, внутренние
  токены, метрики, структура продолжений, область сайдбара, **вывод домена из
  улик страницы** (12), отрицания Википедии, принадлежность фрагментов статьи.
- **Сборка, блокирующие** (`blockingIssues` + типизированные ошибки): разорванные
  цитаты ≥3 стр., внутренние коды ≥3 стр., панель спорит с текстом ≥3 стр.,
  **повтор текста ≥1 стр.**, таблица без строк, адрес дважды, абзац сверх
  бюджета, потеря при перекладке, текст без носителя, потеря при разбивке.
- **Отрисовка**: `CONTENT_DROPPED_BY_RENDERER`, `RENDER_TELEMETRY_MISSING`,
  `COMPLIANCE_CARD_CLIPPED`.
- **Оркестратор/инфраструктура**: входы подготовки, манифест, счётчики
  сборки/рендера, ворота готовности (структурные), падение рендерера,
  провайдеры — возобновляемые, вне рамок.

## 3. Принцип

**Ворота — последняя линия, а не первая.** Состояние, которое они отвергают,
должно быть недостижимо для построителей; где недостижимость нельзя доказать
— сборка чинит сама и пишет в журнал, а не останавливается. Жёсткий стоп
остаётся только тому, что действительно нельзя отдавать: выдуманный
источник, потеря содержательного блока рендерером, пустая дека, структурные
инварианты. И у каждого отказа — поле, текст и мера.

## 4. Что делается

1. **Реплей настоящего прогона офлайн** — `scripts/replay-deck-from-job.ts
   <каталог джобы>`: `analytics/` → сборка с мерой рендерера → payload →
   отрисовка локальным Python → суд телеметрии и проверок сборки; код 1 при
   любом блокере. Первый корпус — 0053 (в scratchpad). Отныне дефект деки
   воспроизводится на столе, а не в проде.
2. **Страница AI-ответов**: сайдбар базового листа получает полную колонку —
   как у всех панелей; тела ответов идут только на продолжения
   (`firstPageBullets: 0`). Проверяется реплеем на настоящем payload 0053:
   потерь рендерера ноль. Отвергнутая альтернатива — ужать бюджет сайдбара до
   ~140 знаков: сайдбар переставал что-либо говорить.
3. **Мера сайдбара до фиксации**: `measure_orion_golden` отдаёт и потери
   сайдбара; цикл `runDeckBuildMeasured` при потере на слайде X пересобирает
   его панель с меньшим бюджетом колонки. Страховка для всех панельных
   страниц, не только AI.
4. **Смок ёмкости на объявленных бюджетах** (Python, офлайн): каждый шаблон с
   сайдбаром рисуется с полями на **максимуме** объявленного бюджета
   (660 знаков колонки, две подсветки по 240), буллеты — на
   `maxBulletCharsPerSlide`; телеметрия без единой потери. Это доказательство
   на границе, а не на образцах.
5. **Починка повтора в сборке**: два одинаковых блока на странице — второй
   снимается до проверки, с записью в журнал; ворота остаются растяжкой.
6. **Синтетический враждебный корпус** (тест, коммитится): бандл формы 0053 —
   одинаковые тела карточек, кириллический бренд в заголовке, пропущенный
   пробел, ответ ИИ на 1100+ знаков, строки без улик, IDN, ники с
   подчёркиванием, коды заглавными в заголовках, десять подсвеченных строк.
   Сборка: `blocking` пуст, все секции прошли.

Вне рамок: гейты аналитики (прошли на самой тяжёлой форме; реплей аналитики —
отдельный шаг), провайдеры и инфраструктура, `fixtures/namesake-case/`.

растровый смок, новый смок ёмкости, реплей 0053 с кодом 0. Мутации на местах
починки. Эталоны читаются вслух.
