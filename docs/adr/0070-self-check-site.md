## Задача и границы

Этап готовит почву и не создаёт ни одной публичной страницы и ручки.

В рамках:

1. Ветка `feature/self-check-site` от `main` без слияния веток разработчика; сверка ТЗ 1.6.
2. Локальный стенд без Docker.
3. Дата рождения — обязательное поле дела: схема создания, форма админки, словари.
4. Проверка ИНН по контрольным разрядам — чистая функция `src/modules/self-check/inn.ts`.
5. Настройки сайта из приложения D ТЗ со значениями по умолчанию, ключи капчи в `.env.example`,
   сводка настроек сайта в логе старта.
6. Каркас раздела «Самопроверка с сайта» в `docs/ENGINEERING.md`.

Вне рамок: таблица `dp_self_checks`, ручки `/api/self-check/*`, проверка капчи (этап 2); лёгкий
прогон и вердикт (этап 3); страницы (этапы 4–5); совместимость тестов и раннера смоков с Windows.
Настройки этапа 1 пока читает только сводка — остальные потребители появляются на этапах 2–5.
Эталоны, `DECK_CONTENT_VERSION` и дека не трогаются.

## Решения реализатора

1. **Строковые настройки, где регистр — часть значения** (адрес сайта, id Метрики, коды
   верификации), — `TEXT_DEFAULTS` и `textSetting`, а не `STRING_DEFAULTS`: `stringSetting`
   приводит к нижнему регистру. Два чтения отвечают на разные вопросы — «какой вариант выбран» и
   «какое значение задано».
2. **Числовые настройки** — `NUMBER_DEFAULTS` и `numberSetting` с нижней границей. Непонятое
   значение читается как значение по умолчанию (как у переключателей), меньшее границы — как
   граница. Граница у лимитов — 1: остановить проверку — работа рубильника `SELF_CHECK_ENABLED`,
   второй ответ «ноль в лимите» не заводится. Опрос статуса — не чаще 5000 мс (ТЗ, раздел 4).
3. **Сводка настроек сайта** — отдельная `describeSelfCheckSettings`, а не строки
   `describeCapabilityReadiness`: сайт не сборщик, капча не источник.
4. **Ключи капчи** `SMARTCAPTCHA_SERVER_KEY` и `SMARTCAPTCHA_CLIENT_KEY` — в `.env.example` (ТЗ,
   приложение D). Клиентский ключ не секрет, но значения по умолчанию у него нет: он выдаётся на
   домен.
5. **ИНН в тестах** — синтетические (контрольные разряды посчитаны независимо, по алгоритму ФНС)
   и опубликованный ИНН юрлица. ИНН физлиц из прогонов в тесты не берутся.
6. При слиянии с `feature/topvisor` (этап 7) у проверки ИНН будет две реализации — одну удалить.

## Стенд

- **База.** PostgreSQL 16.15 через winget (`PostgreSQL.PostgreSQL.16`, служба `postgresql-x64-16`,
  порт 5432; `pg_hba` пускает только localhost), база `global_info`. Пароль суперпользователя
  случайный и лежит только в `.env` стенда, который не коммитится.
- **`.env`** из `.env.example`: случайные секреты сессии и ссылок, `DIGITAL_PROFILE_MOCK_AGENTS=true`,
  все ключи источников пустые.
- **Схема и данные.** `npx prisma migrate deploy` применил все миграции, `npm run db:seed` завёл три
  демо-дела и четыре демо-пользователя. `npm run db:deploy` на Windows не работает
  (`spawnSync npx ENOENT`), а скрипты под `tsx` не читают `.env` сами — переменные подаются в
  окружение.
- **Процессы:** `npm run dev` и `npm run worker`. В логе старта печатаются строки `САЙТ`.
- **HTTP.** `POST /api/digital-profile/cases` без даты и с пустой датой — 400 с текстом о дате
  рождения в `fieldErrors.birthDate`; с непонятной датой — 400 `Invalid date`; с датой — 201
  (дело DPA-2026-0004, вымышленный субъект).
- **Форма «Создать кейс»** (headless Chrome): у поля звёздочка и подсказка, атрибут `required`;
  отправка без даты на сервер не уходит; при обходе браузерной проверки форма показывает свой текст,
  и запрос тоже не уходит.
- **Демо-прогон.** Панель персоны: Википедия ответила (0 карточек), панель знаний Google и
  OpenSanctions — `NOT_CONFIGURED`; решение «без персоны». Базовый сбор демо-агентами прошёл за
  секунды, стадия обогащения без токена Arsenkin через 41 опрос без продвижения ушла в
  `FAILED_TERMINAL`. `REPORT_READY` на стенде без Arsenkin и рендерера недостижим — точка отсчёта
  этапа: конец базового сбора. Дойдёт ли прогон дальше с `ARSENKIN_ENABLED=false`, не проверялось.
- **Платных вызовов не было:** ключей источников нет; единственное внешнее обращение — бесплатный API
  Википедии для панели персоны.
