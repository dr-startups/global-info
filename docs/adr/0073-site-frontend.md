# 0073. Этап 4 сайта самопроверки: лендинг, мастер проверки, юридические страницы

План этапа 4 по ТЗ `global-info-site-tz-2026-09-11.md` (раздел 7, «Этап 4»). Источник правды для
вёрстки, текстов и движения — утверждённый макет (`prototype.html`, `site.css`, версия 18), он лежит
вне репозитория; для данных и контракта — ручки этапов 2–3 (`docs/ENGINEERING.md` §9).

## Задача и границы

Посетитель проходит путь в браузере на локальном стенде: лендинг `/` с формой → `/check/[publicId]`
«Кто из них вы?» → запуск → ожидание → один из трёх результатов → заявка → «спасибо», и видит каждый
отказ из ТЗ 2.4 словами. Экран рисует только то, что отдают публичные ручки.

Входит:

1. Разделение layout: корневой — `<html lang="ru">` и `<body>`; `src/app/admin/layout.tsx` — шапка
   админки и `globals.css`; `src/app/(site)/layout.tsx` — шапка и подвал сайта, `site.css`, шрифты,
   metadata по умолчанию. `src/app/page.tsx` (редирект в админку) удаляется.
2. `site.css` макета → `src/app/(site)/site.css` с правками переноса (ниже); шрифты →
   `src/app/(site)/fonts/`; кадр закрывающего листа → `public/site/` (не импортом модуля: объявления типов
   картинок даёт `next-env.d.ts`, а его нет в CI на шаге «Типы»).
3. Компоненты `src/modules/site/components/` — те, из которых собраны экраны этапа.
4. Лендинг со всеми блоками макета; форма на общей схеме, капча при заданном ключе, ловушка.
5. Мастер: экран по проекции статуса, «Это вы?», запуск, опрос, три результата, заявка, «спасибо»,
   служебные экраны.
6. Юридические страницы — черновики — и `not-found`.
7. Метрика: `track()` и цели; `noindex` на `/check`.
8. `docs/ENGINEERING.md` §9: структура `(site)`, правило «ничего из `(site)` не ходит в базу на
   сборке», тонкий клиент, конфиг сайта.

Вне рамок: страницы этапа 5 (`/uslugi`, `/voprosy`, `/o-proekte`, `/kontakty`, `/blog`), `robots.ts`,
`sitemap.ts`, `manifest.ts`, иконки, OG-картинка, JSON-LD, canonical и индексация по
`SITE_INDEXING_ENABLED`; заголовки безопасности, обезличивание по сроку и `README.md` — этап 6; код
`404` у несуществующего `publicId` (страница мастера клиентская — экран «не найдена» отдаётся с кодом
`200`; код — пункт технического SEO этапа 5); правки бэкенда сверх названных ниже. Эталоны и
`DECK_CONTENT_VERSION` не меняются.

## Решения владельца

| Вопрос | Решение | Когда |
|---|---|---|
| «AI-анализ» в текстах макета (ТЗ §9) | Оставить как в макете, в том числе в подписи стадии ожидания. Лёгкий прогон GPT не вызывает — расхождение текста с кодом названо владельцу и принято им | 15.09 |
| Зарубежные сервисы в черновиках политики и согласия | Писать фактом; страница заметно помечена «черновик, на проверку юристу» | 15.09 |
| «Услуги», «Блог», «О проекте» в шапке и подвале до этапа 5 | Как в макете: до этапа 5 ведут на 404 | 15.09 |
| Lighthouse и запись экрана для приёмки | Скачать через `npx` (lighthouse, ffmpeg Playwright); в `package.json` не попадают | 15.09 |
| Экран «Проверка временно недоступна» | Без формы: контакты при выключенном рубильнике не собираются | 14.09 |
| Стадии ожидания | Две — `collecting`, `verdict` | 15.09 |
| Шкала риска | Три ступени `risk-scale.ts` | 15.09 |
| Негатив без темы каталога | «Негатив найден»; экран рисует число материалов без названия темы | 15.09 |

## Умолчания, объявленные владельцу 15.09

- **`globals.css` — только в `admin/layout.tsx`**, а не в корневом, как пишет ТЗ 3.1: он ставит
  `html { font-size: 14px }`, и все `rem` сайта считались бы от 14 px.
- **Настройки, меняющиеся без пересборки, статическая страница берёт из `GET /api/site/config`**
  (`selfCheckEnabled`, `captchaClientKey`, `metrikaId`). Образ собирается без переменных, и прочитанное
  при `next build` вшилось бы пустым: на площадке форма уходила бы без токена капчи и получала `400
  CAPTCHA_FAILED`, а выключенный рубильник не прятал бы форму. Локально `next build` читает `.env`,
  поэтому на стенде такая ошибка не видна.
- **Отказы создания, у которых ещё нет проверки**, — `/check/limit` (`429`) и `/check/disabled` (`503
  SELF_CHECK_DISABLED`); вид — служебные экраны мастера.
- **Экраны, которых демо-стенд не даёт** (негатив, чисто, прервалась, срок истёк, другой браузер,
  лимит), для приёмки снимаются на настоящем мастере с подменой ответов API в Playwright; в базу стенда
  ничего не пишется, на скриншотах это подписано.
- **«Изменить данные»** ведёт на пустую форму: ФИО и дату рождения браузер не хранит.

## Решения реализатора

- **Подписи стадий — один ответ.** `RUN_STAGE_LABELS` уезжает из `public-dto.ts` в
  `self-check/run-stages.ts` без серверных зависимостей: его читают проекция статуса (`stageLabel`) и
  экран ожидания (список стадий «готово / идёт / ожидает»). Подписи — из макета в форме двух стадий:
  «Поиск упоминаний и сверка с открытыми источниками и санкционными списками» и «AI-анализ размечает
  находки и формирует результат» (решение владельца об «AI-анализ»). Тест этапа 3
  `self-check-status-maps-stages-to-words` ждёт прежних подписей — правка его ожидания называется
  отдельной строкой.
- **Шкала — из `risk-scale.ts`:** слова ступеней — `CLIENT_RISK_LABELS`, делений три. В `site.css`
  подписи шкалы — три колонки, модификаторы `--critical` у шкалы и вердикта удаляются.
- **Сводка негатива не приписывает материалы темам, о которых не знает.** `materialsFound` —
  различные негативные материалы, счёт темы — материалы темы; материал бывает и в двух темах, и без
  темы. Сумма счётов тем не меньше числа материалов — «N материалов в K темах», как в макете; меньше —
  «N материалов; темы определены не для всех»; тем нет — «N материалов; тему для них определить не
  удалось» и одна группа плашек без названия темы.
- **Ответы источников** — по `sourcesChecked`, четыре группы: поисковая выдача; картинки, видео и
  подсказки; открытые источники; санкционные и PEP-списки. У «данных недостаточно» причина — по
  данным: поиск не ответил — «не ответила поисковая выдача», ответил — «поисковая выдача не вернула
  материалов по этому имени».
- **Тонкий клиент** `src/modules/site/api.ts`: разбирает конверт и не бросает; сетевой сбой — отказ
  `NETWORK_ERROR`; на вход админки не уводит, в отличие от `client/api.ts`.
- **Опрос** — только у `RUNNING`, по `run.nextPollMs`, но не чаще раза в 5 с; конечный статус опрос
  останавливает; скрытая вкладка гасит таймер, возврат сразу спрашивает статус.
- **Капча** — невидимая SmartCaptcha: `captcha.js?render=onload`, `render({ sitekey, invisible: true,
  callback })`, `execute()` при отправке. Скрипт грузится только при `captchaClientKey`; уведомление
  об обработке данных SmartCaptcha не скрывается — это обязанность оператора. На стенде ключа нет:
  ветка с ключом вживую не гонялась, и отчёт это говорит.
- **Метрика** — один `track()`; счётчик подключается, только если задан `metrikaId`; вебвизор
  выключен (формы с ПДн).
- **Шрифты** — `next/font/local`: Golos Text одним вариативным woff2 (кириллица и латиница, 79 КБ),
  Literata 600 — только латиница логотипа (22 КБ). Имя семейства `next/font` генерирует сам, поэтому
  токены шрифтов `site.css` получают значение на обёртке `.site-body`, где объявлены переменные
  шрифтов.
- **Правки `site.css` при переносе**, всё остальное — как есть: переводы строк LF; убраны отсылки к
  `design-brief.md` и `tools/measure-motion.mjs`; `body.site-body` → `.site-body` (класс на `<body>`
  вложенный layout поставить не может) и токены шрифтов на ней; шкала — три деления; класс ловушки
  `.site-hp` (в макете ловушку прятал `.proto-hp` из `proto.css`).
- **`CONSENT_VERSION`** меняется вместе с появившимся текстом согласия: `draft-2026-09-15`.
- **Корневой `not-found.tsx`** рисуется в корневом layout, без layout сайта, — поэтому сам подключает
  `site.css` и общий каркас сайта.
