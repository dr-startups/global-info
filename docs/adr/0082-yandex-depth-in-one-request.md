# 0082 — Глубина Яндекса одним запросом

## Что чинить

Адаптер органики Яндекса (`providers/yandex-search-provider.ts`) берёт двадцатку двумя
синхронными запросами по десять: `groupSpec` в теле не шлётся, страница — десять групп,
цикл идёт за следующей, пока первая полна. Это два дефекта сразу.

1. **Деньги.** Каждая страница — отдельный оплаченный запрос (0,488 ₽ днём). Живой лёгкий
   прогон 24.09.2026: счёт Яндекса 23,14 ₽ = нейро-ответ 5,08 ₽ + 37 синхронных запросов,
   из них 16 — вторые страницы запросов ORION (≈ 7,8 ₽, треть счёта). Тариф — за запрос, не
   за число результатов (`aistudio.yandex.ru/docs/ru/search-api/pricing`).
2. **Две страницы — два разных снимка выдачи.** Живая проверка 24.09.2026 по разрешению
   владельца (нейтральный запрос «погода в Москве», три запроса, 1,46 ₽): страницы 0 и 1
   ответили разные реплики (`found` 1 184 219 и 1 042 272, разные `reqid`), и два адреса из
   десяти второй страницы повторили первую — вместо двадцати разных результатов восемнадцать,
   а места 11–20 взяты из чужого ранжирования. Один запрос с `groupsOnPage: 20` вернул
   двадцать групп одного снимка.

Попутно опровергнуто опасение из документации Яндекса («`groupsOnPage` по умолчанию 20»):
без `groupSpec` ответ — `groups-on-page="10"`, `mode="deep"`, `docs-in-group="1"`, то есть
вторая страница действительно была местами 11–20, сдвига позиций нет.

## Как

- `buildYandexV2Body` принимает `groupsOnPage` и шлёт `groupSpec` с группировкой, которую
  Яндекс и так применял сам (`GROUP_MODE_DEEP`, `docsInGroup: 1`) — меняется только число
  групп на странице.
- `search` делает **один** запрос: `groupsOnPage` = запрошенная глубина (`resolveSearchDepth`,
  потолок `YANDEX_MAX_RESULTS_PER_QUERY` = 50 ≤ 100 у API). Цикла по страницам больше нет.
  Короткий ответ — это всё, что есть у Яндекса по запросу; второго запроса за ним нет.
- `DEPTH_IS_BILLED.yandex = false` в `search-depth.ts` становится правдой: глубина у Яндекса
  входит в цену запроса. Комментарий переписывается под то, как это теперь достигается.
- ENGINEERING §5 «Глубина выдачи» и §9 «Первый живой прогон»: замер и правило.

## Тесты (красные до кода)

`tests/unit/yandex-depth-is-one-request.test.ts`, подменённый `fetch` ведёт себя как API:
отдаёт столько групп, сколько просит `groupSpec.groupsOnPage`, а без `groupSpec` — десять.

1. проба ORION (глубина 20) — ровно один запрос, `groupsOnPage` "20", `page` "0",
   двадцать результатов с позициями 1–20;
2. агент по умолчанию (глубина из настроек, 10) — один запрос, `groupsOnPage` "10";
3. глубина 50 — один запрос, `groupsOnPage` "50";
4. короткий ответ (15 групп на просьбу о 20, как у запросов ORION 24.09) — пятнадцать
   результатов и **один** запрос;
5. группировка в теле — `GROUP_MODE_DEEP`, `docsInGroup` "1".

Правка старого теста (называется в коммите): `free-depth-is-not-rationed` — случай «Яндекс
листает вторую страницу и на пробе» утверждает старое поведение (`pages = ["0","1"]`);
переписывается на «проба просит двадцать одним запросом».

Мутации: убрать `groupSpec` из тела — тесты 1–3, 5 краснеют; вернуть цикл «дособирать до
глубины» — тест 4 краснеет.

## Вне рамок

Serper (решение владельца 24.09: кредиты Serper не экономим), нейро-ответ Яндекса (остаётся),
отложенный режим Яндекса (в 16 раз дешевле, но минимум 5 минут — лёгкому прогону не годится),
повтор запросов агента Яндекса и ORION (≈ 1 ₽).
