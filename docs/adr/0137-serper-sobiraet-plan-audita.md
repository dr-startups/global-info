# 0137 — Serper собирает план аудита, а не личный набор из трёх запросов

Шаг 0136 дал таблице Google настоящие адреса и **отнял охват**. Измерено на прогоне Галицкого
(DPA-2026-0070, 58 страниц, 20.09.2026):

* Serper вернул **19 органических строк по одному запросу, позиции 1–9, только по России**;
* Topvisor раньше давал 403 строки по 25 запросам в двух контурах — без адресов, но давал;
* стр. 19: «Россия — Google, позиции 1–9 из ТОП-20 … Позиции 10–20 не вернул ни один источник
  выдачи в этом прогоне» — по смыслу неправда: их никто не спрашивал;
* стр. 47: «ОАЭ — позиции в поисковой выдаче. Органическая выдача по данному контуру проверена:
  материалов нет» — **контур ОАЭ лишился органики целиком**.

## Причина

Базовый сборщик Google ходит по личному набору запросов, а не по плану аудита:

* `buildPersonSearchQueries` с `maxQueriesPerAudit = 3` (умолчание `GOOGLE_SEARCH_MAX_QUERIES_PER_AUDIT`);
* все запросы получают **один** регион (`primaryRegion`), поэтому ОАЭ не собирается вовсе;
* глубина — `providerConfig.google.resultsPerQuery`, а не глубина аудита.

Topvisor ходил по `offlineOrionQueryPlan` — плану аудита, у которого есть регионы и глубина
`SERP_AUDIT_DEPTH`. Тесты шага 0136 этого не поймали: они проверяли, **кого зовут**, а не сколько
тот приносит.

## Что делается

**У движка, который собирает позиции, запросы берутся из плана аудита.** План — один на продукт
(`offlineOrionQueryPlan`), и второй набор запросов для той же выдачи заводить нельзя.

1. `agents/real/real-search-agent-base.ts` — хук `auditSearchSpecs(subject)`. Вернул набор —
   агент идёт по нему; вернул `null` — прежний личный набор, и остальные агенты не меняются.
2. `agents/real/real-google-search-agent.ts` — хук отдаёт план аудита, когда
   `POSITIONAL_SERP_SOURCE.GOOGLE === "serper"`: по запросу на регион плана, код региона и язык из
   `regionProfile` (`RU → ru`, `UAE → ae`), глубина `SERP_AUDIT_DEPTH`.

**Попутно — цитата основания рамки печатается через `quoteBody`.** Стр. 26 отчёта Галицкого:
`«Президент и владелец футбольного клуба « Краснодар »»` — внутренние ёлочки не стали лапками, и
внутри остались пробелы. Тот же дефект, что чинил шаг 0131, в другом месте: строка собирается
склейкой `«${quote}»` в `fragment-builders/shared.ts` и общую чистку не зовёт.

## Чем проверяется

- `tests/unit/google-collects-the-audit-plan.test.ts`: у Google набор запросов равен плану аудита,
  включает оба региона, глубина — глубина аудита; у остальных агентов набор прежний.
- дополнение в тесте основания рамки: внутренние ёлочки становятся лапками, `»»` не бывает.
- Мутации: вернуть личный набор — тест краснеет; убрать `quoteBody` — краснеет второй.

## Вне рамок

Сколько именно вызовов Serper выйдет на прогон — считается по факту первого прогона, не гадается.
Владелец сказал, что ограничения по деньгам нет.
