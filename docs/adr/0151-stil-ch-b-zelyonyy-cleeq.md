# 0151 — Стиль «ч/б + зелёный cleeq»: заголовки капсом, крупные цифры, метка раздела, разделитель-обложка

**Статус:** шаг идёт. Ветка — `dis`; проверка локально на эталоне report-72, затем на тесте.
ADR-0150 закрывается вместе с этим шагом, когда владелец примет вид на тесте.

## Что просили

Владелец, 24.09.2026, положил два примера. `Primer 1.pdf` — наша же старая версия («ORION Digital
Profile»: тёмно-синий, DejaVu Sans) — ориентиром не является. `Primter 2.pdf` — коммерческое
предложение агентства Reputation House (PowerPoint, 89 страниц) — ориентир «по дизайну именно».

Что у них сильнее: жирные заголовки капсом; крупные цифры-итоги; строгая палитра — ч/б и один
акцент; метка раздела справа сверху на каждом листе; разделители разделов с фото на полосу;
графики и тепловые карты позиций. Что у нас сильнее и сохраняется: каждое утверждение
прослеживается до источника; снимки выдачи с объяснением в боковой панели.

## Решения владельца

1. Стиль **«ч/б + зелёный cleeq»**: нейтральные серые вместо мятных, один фирменный акцент —
   зелёный #24D875, красный — только для негатива; фиолетовый и голубой уходят. Фирменные цвета
   конкурента (чёрный и красный, Arial Black) не копируем: это их узнаваемый стиль, а красный у нас
   значит «негатив».
2. **Заголовки капсом**, одним кеглем.
3. **Крупные цифры** в плитках метрик — ради них меняется правило ADR-0008 п.3 (ниже).
4. **Метка раздела** справа сверху.
5. По графикам владелец спросил мнение сессии: **разделитель-обложка — в этом шаге** (только
   рендерер, в замер текста не входит); **кольцо состава выдачи и тепловая полоса позиций —
   следующим шагом**: им нужны данные от построителей (новое поле нагрузки, подъём версии деки,
   окно деплоя).

## Где и как

Всё — в `renderer/orion_golden_render/`. TypeScript не трогается: `DECK_CONTENT_VERSION` не
поднимается, нагрузка рендерера не меняется, окна деплоя нет. Мера (`measure_orion_golden`) и
вывод рисуются одним кодом, поэтому капс и выросшие плитки сборка деки учитывает сама.

| Правка | Место |
|---|---|
| Палитра | `common.py`: `PAGE_BG` #F7F7F7, нейтральные `STAGE_SHADOW`, `CARD_BORDER`, `MUTED_COLOR`, `COVER_SUBTITLE`, `ACCENT_SOFT`; фиолетовый и голубой — вне употребления |
| Капс | `_Ctx.title`: текст в верхнем регистре до замера и вывода; кегль заголовков светлых страниц — 22 pt |
| Цифры | `layout_cleeq.render_metric_rows`: один кегль чисел на страницу — крупнейшая ступень (36, 26, 20), при которой все значения встают в строку |
| Метка раздела | `api.py`, цикл по листам: раздел — по оглавлению деки (`deckManifest.toc`); поисковую систему лист выдачи называет в заголовке сам, отдельным полем она в нагрузку не едет |
| Разделитель | `slides.py`, `orion_golden_region_divider`: ч/б затемнённый снимок выдачи региона панелью справа; снимка нет — полосы бренда |

### Изменение правила ADR-0008 п.3

Было: «на странице ровно один элемент первого уровня». Крупная цифра плитки при нём невозможна —
пять чисел одного кегля сами были бы пятью элементами первого уровня. Стало: ключевые цифры
плиток — отдельная роль (рамки `orion_metric_value_*`), и правило считается по остальному тексту
страницы; первым уровнем остаётся заголовок. Шкала кеглей и «не больше четырёх ступеней на
странице» не меняются: чисел на странице — один кегль.

## Проверка

- `npx tsx scripts/run-orion-deck-sections-report72.ts` — ворота после каждой правки; число страниц
  «до/после» называется (капс и выросшие плитки могут добавить продолжения).
- Все смоки рендерера; ожидания, которые держали прежние решения (ряд плиток 600 000, кегли
  {22, 20, 11, 9}, один первый уровень с числами), меняются вместе с правилом — каждое названо.
- `npm run typecheck`, `npm test`; GitHub CI после пуша.
- Глазами владельца: «до/после» локально, затем пересобранный отчёт на тесте.

## Вне рамок

Графики (кольцо состава выдачи, тепловая полоса позиций) — шаг 0152. Смена фирменного шрифта,
полосы тона у заголовков разделов по долям негатива, сокращение текста на листах (это построители).
