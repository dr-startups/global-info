# ADR — решения по глобальной переработке

Каждый файл — **одно решение и один шаг работ**. После каждого шага проводится
глобальное тестирование; критерии приёмки записаны в самом файле, в разделе
«Глобальное тестирование после шага».

Формат намеренно короткий: контекст с измеренными фактами, решение,
последствия, критерии проверки. Всё, что утверждается в разделе «Контекст»,
взято из кода на `main` или из эталонного прогона `baselines/report-72` — со
ссылкой на файл и строку, чтобы решение можно было перепроверить, а не принять
на веру.

## Почему первым шагом идёт не текст

Приоритет 1 — текст отчёта, и работа по нему начинается сразу после 0001.
Но требование «весь код должен работать сразу, нет времени на исправление
ошибок после ручного тестирования» невыполнимо при нынешнем гейте:
`npm run ci:smokes` завершается **кодом 0**, не выполнив ни одной проверки
(`# pass 0, # cancelled 10`). Пока это так, ни один из восьми оставшихся шагов
нельзя принять иначе как показом с экрана. 0001 — это цена входа, а не отдельная
задача.

## Что измерено до начала работ

Короткая сводка фактов, на которых стоят решения. Подробности — в файлах.

**Текст.** Схема слайда — анкета из четырёх подписей («Что обнаружено / Почему
важно / Что проверить / Источник»). Промпт требует заполнить все поля и писать
«не короче ~40% бюджета поля». Раздел «Почему важно» — одна из **четырёх**
заготовок на весь отчёт. В готовом тексте: тема повторена трижды подряд,
«4 свидетельств», обрывы на полуслове, поисковые подсказки в роли
доказательств.

**Arsenkin.** 12 слотов в двух стадиях. В эталонном прогоне **все 15** ячеек со
статусом «не OK» — Arsenkin с `NO_RESULTS`, и это **вся вторая стадия**:
AI-ответы 0 из 3, индексация 0 из 10. При этом первая стадия даёт 60 наблюдений
органики — единственный её источник. Ограничения аккаунта: 5 задач
одновременно, 30 запросов в минуту, `check-top` — 3–6 минут.

**Презентация.** Шрифт — свободный системный DejaVu Sans, и смена заблокирована
проверкой на старте. Жирный текст меряется метриками обычного начертания —
отсюда выезжающие строки. Запасная оценка ширины считает все символы
одинаковыми. Инспектор геометрии при этом рапортует `overflow: 0`, потому что
проверяет выход **рамки** за границы слайда, а не текста за границы рамки, —
и меряет тем же испорченным инструментом, который создаёт дефект.

**Кабинет.** Опрашивают сервер **2 компонента из 22**; остальные делают один
запрос при монтировании. Стриминга нет нигде. Бэкенд статус отдавать уже умеет —
фронтенд не спрашивает второй раз.

## Как это соотносится с DoD

- «UX в кабинете значительно лучше» — 0009, плюс честное состояние из 0005.
- «Презентация на голову выше» — 0006 → 0007 → 0008, в этом порядке.
- «Полезна целевой аудитории» — 0002 → 0003 → 0004: текст, который читают, и
  факты, которые не превращаются в список ссылок.

Оценка «на голову выше» снимается человеком: это единственный критерий здесь,
который нельзя закрыть автотестом.
