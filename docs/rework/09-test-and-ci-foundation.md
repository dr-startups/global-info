# Шаг 09. Тестовый контур и CI

**Статус:** ГОТОВ К РАБОТЕ (диагноз подтверждён замером)
**Файлы:** `tests/unit/*.test.ts`, `vitest.config.ts`, `.github/workflows/ci.yml`, `package.json`
**Приоритет:** P1 — не влияет на текущий отчёт напрямую, но без него всё
исправленное в Фазах A и B развалится обратно.

---

## Проблема

`npm test` на чистой ветке `full-gpt3`, без каких-либо изменений:

```
Test Files  5 failed | 26 passed (31)
     Tests  165 passed | 1 skipped (166)
```

Пять файлов падают с `Error: No test suite found in file ...`. Причина — они
написаны под **другой раннер**:

```ts
import { describe, it } from "node:test";   // ← встроенный раннер Node
```

тогда как проект гоняет **vitest** (`"test": "vitest run"`). Vitest не собирает
сьюты `node:test`, поэтому файл считается пустым.

Затронуты:

```
tests/unit/arsenkin-region-and-ai-surface.test.ts
tests/unit/canonical-uae-serp-visual-arsenkin.test.ts
tests/unit/composite-serp-ai-uae-heal.test.ts
tests/unit/unified-enrichment-sibling-remap.test.ts
tests/unit/unified-enrichment-targeted-retry-resolve.test.ts
```

Соотношение: 26 файлов на vitest, 5 на `node:test`.

## Почему это важно именно сейчас

Показательно, **что именно** не выполняется. Это тесты на:

- маппинг региона Arsenkin (UAE не должен схлопываться в RU),
- лечение UAE-региона и AI-поверхности при composite-merge,
- ремап sibling-прогонов при возобновлении обогащения,
- разрешение целевого ретрая обогащения.

То есть ровно те механизмы, вокруг которых в истории ветки крутятся последние
коммиты: `fix(arsenkin): restore UAE organic + AI answer surfaces`,
`fix(arsenkin): remap PAA/AI/URL sibling runs on ingest resume`,
`fix(unified): build UAE SERP from Arsenkin`. Тесты писали как страховку от
регрессий — и страховка молча не работает.

CI (`.github/workflows/ci.yml`) выполняет `npm test` как обязательный шаг, значит
пайплайн на этой ветке **красный**, и это перестало быть сигналом.

## Решение

### 09.1. Починить пять файлов (полчаса)

Механическая замена импорта: `node:test` → `vitest`, `assert` из
`node:assert/strict` → `expect` или оставить `assert` (vitest его не запрещает).
Минимальный вариант — только строка импорта `describe/it`.

После починки **обязательно** прогнать и посмотреть, что они не просто
собираются, а проходят: пять сьютов не исполнялись неизвестно сколько времени,
покрываемый ими код с тех пор менялся. Упавшие ассерты здесь — не повод их
ослабить, а найденные регрессии.

### 09.2. Запретить повторение (полчаса)

Правило ESLint или простая проверка в `ci:smokes`: импорт `node:test` внутри
`tests/**` — ошибка. Без этого через месяц появится шестой такой файл.

### 09.3. Закрыть тестами то, что исправлено в Фазах A и C

Тесты, названные в критериях приёмки других шагов:

| Тест | Шаг |
|---|---|
| `real_only` не выбирает ни одного mock-агента | [01](01-evidence-integrity-no-mock-substitution.md) |
| тело запроса к `gpt-5.5` не содержит `temperature`, к `gpt-4o` — содержит | [02](02-gpt-transport-and-model-contract.md) |
| `isPollAuthContentionOnly`: блокировка + реальная ошибка → `false` | [03](03-arsenkin-live-auth-singleton.md) |
| две джобы в одном процессе не блокируют друг друга | [03](03-arsenkin-live-auth-singleton.md) |

### 09.4. Сделать CI осмысленным

Сейчас в CI есть `typecheck`, `npm test` и `ci:smokes` — набор правильный. Проблема
не в составе, а в том, что красный результат никого не останавливает. Минимум:
защита ветки `main` от merge при красном CI.

Отдельно: `npm run typecheck` на ветке выдаёт две ошибки в
`tests/unit/pdf-review-phase-h.test.ts` и `pdf-review-phase-i.test.ts`
(дублирующийся ключ `title`, несовместимое приведение типа). Их тоже нужно закрыть,
иначе `typecheck` в CI бесполезен по той же причине.

## Сделано

### 09.1 — пять файлов исполняются

`describe/it` переведены с `node:test` на vitest (`assert` из Node внутри vitest
работает как есть). Все **16 проверок прошли сразу** — скрытых регрессий в
UAE/composite-контуре не оказалось, хотя риск был реальным: файлы не исполнялись
неизвестно сколько времени.

### 09.2 — запрет на повторение

`tests/unit/test-runner-consistency.test.ts`: ни один файл в `tests/unit` не
импортирует `node:test`, и каждый объявляет хотя бы один `describe`. Второе
ловит и другой способ получить «пустой» файл.

### Typecheck

Две давние ошибки в `pdf-review-phase-h/i` исправлены: дублирующийся ключ
`title`, перекрываемый спредом, и приведение неполной фикстуры к `Finding` —
теперь через `unknown`, чтобы неполнота была явной. `npm run typecheck` чист.

### Регрессия, найденная офлайн-смоками

`smoke-report-quality-summary` падал на `materialThemes[].sourceDomains` с
`min(1)`. Причина — шаг 05.3: убрана подстановка «неизвестный источник», которая
раньше искусственно наполняла список. Контракт ослаблен: пустой список доменов
законен, выдуманный источник — нет. **Смок поймал то, что `npm test` пропустил** —
довод в пользу того, чтобы держать смоки в одном гейте с юнит-тестами.

`smoke-golden-case` показал расхождение с эталоном: слайдов 43 → 51, с контентом
39 → 47. Причина того же происхождения: инвариант больше не выбрасывает материал
без домена, поэтому до отчёта доезжает больше доказательств. Изменение осознанное
и в нужную сторону — эталон обновлён.

## Остаётся: смок, зависящий от артефакта конкретной машины

Про интерпретатор Python: `smoke:client-text-contract` и
`smoke:orion-golden-render-imports` вызывали бинарник `python`, которого во
многих окружениях нет (в CI выручал `setup-python`). Оба закрыты в рамках
шага 10 — интерпретатор выбирается из `$PYTHON`, `python3`, `python`.

- **`smoke:orion-deck-sections`** читает
  `storage/digital-profile/qa-first36-canary/<caseId>/<runId>/report-assets.json`.
  Весь `/storage/` находится в `.gitignore`, и под git этого файла нет **ни
  одного**. То есть гейт зависит от артефакта конкретной машины и на чистом
  клоне — включая CI — не проходит в принципе. Нужна фикстура в репозитории либо
  вынос смока из обязательного гейта.

Остальные семь смоков зелёные (`smoke:unified-orion-collection` требует
поднятого postgres — на машине без запущенного Docker падает на подключении).

## Критерий приёмки

- [x] `npm test` → `0 failed`; сьютов стало 84 (в момент постановки цели было 31),
      тестов 743;
- [x] `npm run typecheck` → без ошибок;
- [x] импорт `node:test` в `tests/**` ловится автоматически —
      `tests/unit/test-runner-consistency.test.ts`;
- [x] тесты из 09.3 написаны; часть из них писалась по факту дефекта и
      воспроизводит его на сохранённых данных (например `internal-code-scan`
      проверяет правило на деке **до** исправления);
- [~] merge в `main` невозможен при красном CI — `.github/workflows/ci.yml`
      гоняет typecheck, `npm test` и `ci:smokes`; сама блокировка слияния
      настраивается защитой ветки на стороне GitHub и из репозитория не
      проверяется.

## Риски

- Починка пяти сьютов может вскрыть настоящие регрессии в UAE/composite-контуре.
  Это хорошая новость по существу и плохая по срокам: закладывать время на разбор,
  а не на «подвинуть ассерт».
