# Шаг 10. Матрица запросов: служебные токены уезжают в текст запроса

**Статус:** ГОТОВ К РАБОТЕ (воспроизведено на прогоне с полным покрытием провайдеров)
**Файлы:** `src/modules/digital-profile/search-surfaces/orion-query-plan.ts`
**Приоритет:** P1 — тратит платные вызовы и засоряет корпус мусорными результатами.

---

## Проблема

Поверхности выдачи (подсказки, похожие запросы, изображения, видео) запрашиваются
**текстовым поиском по названию поверхности**, а не чтением соответствующего поля
ответа провайдера.

`orion-query-plan.ts:374-384`:

```ts
[
  ["suggestion_lookup", "подсказки"],
  ["related_lookup", "похожие запросы"],
  ["wikipedia_lookup", "биография wikipedia"],
].map(([purpose, suffix]) =>
  mkRow({ queryText: `${profile.fullName} ${suffix}`.trim(), ... })
)
```

и для международного контура (`:529-537`):

```ts
[
  ["suggestion_lookup", "autocomplete"],
  ["related_lookup", "related queries"],
]
```

Аналогично приклеивается контекстный хинт региона (`:424`): `queryText: \`${b} ${hint}\``.

## Доказательство

Реальные строки `query` из `dp_search_surface_items` после прогона:

```
RU:   «Павел Валерьевич Дуров подсказки»
      «Павел Валерьевич Дуров похожие запросы»
      «Павел Валерьевич Дуров публикация»
UAE:  «Pavel Valerevich Durov autocomplete»
      «Pavel Valerevich Durov related queries»
      «Pavel Valerevich Durov image»
      «Pavel Durov RU»
      «Pavel Durov UAE»
```

То есть в Google уходит буквальный запрос «Павел Валерьевич Дуров похожие запросы».
Это осмысленный поисковый запрос ровно в том смысле, в каком осмыслен запрос
«Иван Иванов список файлов» — Google вернёт страницы, где рядом встречаются имя и
слова «похожие запросы».

## Почему это плохо

1. **Платные вызовы впустую.** Три лишних запроса Serper на регион на вариант имени.
   На матрице из пяти вариантов × два региона это десятки оплаченных вызовов за
   прогон, возвращающих шум.
2. **Мусор в корпусе доказательств.** Результаты по бессмысленному запросу попадают
   в тот же корпус, что и настоящая выдача, и дальше участвуют в тематизации.
   С учётом подстроковых регексов (шаг 06) такой шум легко становится «риском».
3. **Поверхности остаются пустыми.** Подсказки и похожие запросы у Serper приходят
   **полями обычного ответа** (`relatedSearches`, `peopleAlsoAsk`), а не отдельным
   поисковым запросом. Запрашивая их текстом, система гарантированно не получает
   настоящую поверхность — отсюда пустой слайд `p11_ru_suggestions_yandex`
   с причиной `no-suggestions` в предыдущем отчёте.
4. **Регион в тексте запроса.** «Pavel Durov UAE» смещает выдачу в сторону страниц,
   где буквально написано «UAE», вместо того чтобы задать регион параметром
   `gl=ae`, который у Serper для этого и предназначен.

## Решение

### 10.1. Поверхности — из полей ответа, а не отдельным запросом

Один запрос на вариант имени → из ответа берутся `organic`, `relatedSearches`,
`peopleAlsoAsk`, `images`, `videos`, `knowledgeGraph`. Адаптер уже есть частично
(`providers/serper-surfaces.ts`) — нужно, чтобы план запросов перестал плодить
текстовые «псевдо-поверхности» и опирался на него.

Экономия: минус 3–5 платных вызовов на регион на вариант, при **росте** полноты
поверхностей.

### 10.2. Регион — параметром, а не словом в запросе

Убрать приклеивание региональных хинтов к `queryText`; регион задаётся `gl`/`hl`,
которые в конфиге уже описаны (RU `ru/ru`, UAE `ae/en`, INT `us/en`).

### 10.3. Ревизия остальных суффиксов

Пройти по всем шаблонам `queryText` (строки 339, 359, 384, 424, 442, 460, 478, 495,
512, 537) и разделить: где суффикс — **осмысленный поисковый термин**
(«биография», «интервью», «wife», «abu dhabi» — это нормальные запросы, они дают
настоящую разную выдачу), а где — **название технической поверхности**
(«подсказки», «autocomplete», «related queries», «image», «publication»).
Первое оставить, второе убрать.

## Сделано

### 10.1 — поверхности больше не запрашиваются по имени

План перестал порождать строки с назначениями `suggestion_lookup`,
`related_lookup`, `image_lookup`, `video_lookup`. Эти назначения остались в
словаре — ими размечаются уже собранные поверхности, — но запросом за ними
никто не ходит. Подсказки, похожие запросы, изображения, видео и блок знаний
как приходили полями ответа `serperAllSurfacesForQuery`, так и приходят: они
читаются из ответов на запросы `subject_lookup` и `media_lookup`.

Правило записано в шапке `orion-query-plan.ts`, чтобы не вернулось:
**строка плана — это запрос, который набрал бы человек.**

### 10.2 — регион параметром, а не словом

`toSubjectProfile` отбрасывает из контекстных хинтов коды регионов
(`RU`, `UAE`, `AE`, `INTERNATIONAL`, `EU`, `US`, …). Регион и раньше задавался
через `gl`/`hl` в `serperBody`, так что дублирование в тексте запроса ничего не
добавляло, а выдачу смещало.

Побочно вскрылось, что прежний код брал **первые два** хинта из
`[...targetRegions, location]` — то есть до `location`, единственного
осмысленного, очередь не доходила никогда. Теперь `Abu Dhabi` попадает в
запрос, а `RU` и `UAE` — нет.

### 10.3 — ревизия суффиксов

| Суффикс | Решение |
|---|---|
| «подсказки», «похожие запросы», `autocomplete`, `related queries` | убраны — названия поверхностей |
| `image`, `photo`, `video` | убраны — поверхность берётся с эндпоинтов `/images`, `/videos` |
| «фото», «видео» | убраны по той же причине |
| «публикация» | убрана — не поисковый термин; на её месте «новости», парная к `news` |
| «интервью», `news`, `profile`, `interview`, «биография wikipedia» | оставлены — настоящие запросы с разной выдачей |

### Замер на контрольном субъекте

Субъект «Дуров Павел Валерьевич», регионы RU + UAE + INTERNATIONAL, риск-пробы
включены:

| | до | после |
|---|---|---|
| строк в плане | 66 | 48 |
| строк, идущих в платный сбор поверхностей | 36 | 18 |
| вызовов Serper на сбор поверхностей | **144** | **72** |

Каждая такая строка — четыре вызова Serper (`/search`, `/images`, `/videos`,
`/autocomplete`), поэтому экономия ровно вдвое. Исчезли, в частности, запросы
`Durov Pavel Valerevich RU`, `Pavel Durov UAE`, `Durov Pavel Valerevich image`,
`Дуров Павел Валерьевич похожие запросы`.

Обещанного планом **роста** числа поверхностей ждать не следует: подсказки и
похожие запросы и раньше собирались из ответов на обычные запросы, а исчезнувшие
строки давали автодополнение по бессмысленной фразе. Ожидается снижение объёма
при росте доли осмысленного — проверяется на живом прогоне.

### Попутно

`smoke-orion-search-surfaces-foundation` падал на проверке
`RU primary queries count <= 5` (было 14) **до** этого шага: она сравнивала cap
на варианты имени со всеми строками приоритета `primary`, куда входят ещё и
бизнес-, медиа- и wikipedia-якоря. Проверка приведена к документированной
семантике (варианты имени, `subject_lookup`), а сам смысл `maxPrimaryPerRegion`
описан в типе опций.

## Критерий приёмки

- [x] ни один `query` в `dp_search_surface_items` не содержит названия поверхности
      («подсказки», «autocomplete», «related queries», «image», «video»);
- [x] ни один `query` не содержит кода региона («RU», «UAE») как слова;
- [x] поверхности `SUGGESTION` и `RELATED` наполняются из полей ответа провайдера;
- [x] число платных вызовов на прогон снизилось (144 → 72 на контрольном
      субъекте); формулировка «а число поверхностей выросло» оказалась неверной
      по существу — см. замер выше.

Первые три пункта закреплены тестами `tests/unit/query-plan-service-tokens.test.ts`
и проверками в `scripts/smoke-query-plan-r52.ts`.

## Примечание

Транслитерация для международного контура работает корректно — план формирует
`Pavel Durov`, `Pavel Valerevich Durov` и осмысленные англоязычные варианты
(`pavel durov abu dhabi`, `how pavel durov get uae citizenship`). Эта часть матрицы
сделана хорошо и переработки не требует.
